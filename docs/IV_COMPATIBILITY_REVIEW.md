## 结论与证据

基准仓库：`haoyu9189-code/InJunction`，检查时 `main` 为 `74a7ba1`。

提供的 `IV-0.001.rar` 含 3 份 TDMS 文件。每份都能正常读取，包含 `STM` 组中的 `Bias (V)`、`Current (mA)`、`Log(G/G0)`；每通道 2,500,000 个 float64 样本，均为有限值。**与后来补充的旧样本对比，通道名称确实不同，但类型与单位没有改变；空数据的直接原因仍是旧处理规则不适应短平台。**

历史提交 `63ccb16` 的 `ivDataProcessUtils.py:275-277` 用固定切片 `[100:frontCheckB-100]` 和 `[backCheckF+100:backCheckB-100]` 求电导均值。新样本的检查平台常只有几十点，例如首条完整轨迹前后各 39 点；此时切片为空。在这 3 个文件上执行历史处理函数，均复现空均值警告及 `(None, None, None)` 返回值。调用者要求 5 个值，于是出现解包失败；GUI 又将全空结果送到直方图，产生 `min() arg is an empty sequence`。

GitHub 当前基准版本已改用平台实际范围，所以未经本次修复也能解析这组样本。因此，**报错端很可能运行的是较早打包版本**，但未取得该 EXE，不能确认其确切版本。Qt 的 Windows 版本提示并非此次数据崩溃的直接原因。

## 真实旧样本补验（同日补充）

文件 `cis-TPE-4ph-tcb-03-15002024-4-9 16-28-10-2.tdms` 的 3 个通道同样各有 2,500,000 个有限 float64 样本，通道名称为：

- `RT-IO:AO1-Bias Volt. [V]`
- `RT-PV:Current [mA]`
- `RT-PV:Conductance LogG`

同一筛选参数、关闭去电容时，历史 `63ccb16` 产生正反扫各 **32 条**，GitHub 基准 `74a7ba1` 和首版修复 `7add05c` 都产生各 **27 条**。这表明首版虽可读取旧文件，但与历史版本的筛选行为尚不相同；不能仅以“能出图”认定历史结果兼容。

本次补充修复明确识别上述 RT 通道，并在默认 `auto` 策略下保留历史长平台的 100 点边缘剔除。平台太短时安全回退到非空的平台窗口；新机器格式继续使用已验证的当前窗口。**新版在该旧样本上恢复正反扫各 32 条，返回的前 8 个字段（正反扫电压、logI、logG、原始电流）与历史版逐点完全一致。**

历史版还有一个独立问题：筛选曲线后未同步筛选 `meanCond`，导致辅助平均电导与轨迹错位。本次保持它与保留轨迹同步。因而后 2 个平均电导字段有意修正，不宣称全部 10 字段均与历史错误结果相同。例如第 4 条保留轨迹的辅助均值由错配的 -4.753829 改为 -4.117218。

如需复现 GitHub 基准版本的整个平台筛选行为，命令行可指定 `--plateau-mode current`；此旧样本会恢复各 27 条，全部 10 个解析输出字段均与 `74a7ba1` 一致。`--plateau-mode legacy` 可对未命名旧布局显式使用历史窗口规则。阈值没有被自动放宽。

这份真实旧样本已完成读取、分段、绘图和 NPZ 导出；两套依赖环境均回归通过。上述结论仅覆盖提供的样本与列明参数，不代表任意历史 TDMS 协议。

## 本次修复

- 新机器保持当前版本按实际平台范围筛选的行为；已识别旧 RT 布局保留历史长平台窗口。所有布局均补齐单点/空/全非有限平台检查，短平台不会直接做固定 100 点裁剪。
- 按通道名定位 bias/current/logG，包括已实测的 RT 旧通道名称，支持命名通道重排及额外辅助通道；明确标记为 A、mA、µA/uA、nA 的电流统一换算为内部 mA。无法判断或存在歧义时报告错误，不按数值大小猜单位。
- 保留“单组、恰好三个未识别名称通道”旧式按位置读取。部分名称可识别但其余含义不明的文件会拒绝，避免误把原始电导或未知电流单位用于计算。这不是对任意 TDMS 布局的承诺。
- 无有效扫描时固定返回 5 个占位值；处理入口在分段前明确检查，并提供文件名和筛选参数。GUI 可跳过坏文件；全失败时不再提交绘图任务。
- 修复负向起扫的下标错误、最后一条正扫越界，以及跨轨迹拼接风险；正反向半扫描仅在同一周期内拼接。
- 去电容时检查偏移边界，避免负切片回绕或截短；修正 `G/G0` 单位换算。**开启去电容后的电导结果会与旧错误公式不同，不能视为逐点不变。**
- LOWESS/梯度先处理重复电压，再将导数恢复到原扫描顺序，修复反扫导数对应到错误电压的问题。**导数图会与旧错误结果不同。**保持导数数值单位为 mA/V，并补上坐标说明。
- 直方图拒绝无电压数据，成对屏蔽 NaN/Inf，保持 x/y 对应；合法零电流在 logI 中延续旧版的 -3 哨兵值。
- 限制进程池大小，单核机器最少使用 1 个进程；异常时释放进程池并清空旧的基础 IV 结果，恢复窗口。新增图像输出目录创建和图对象关闭。
- 用 Qt `toLocalFile()` 处理拖入路径；识别 `.TDMS` 大写后缀。
- 补 `statsmodels` 依赖并修正无效的 `tqdm>=4.10.0.`；GUI 弹窗和 tslearn 改为按需导入，让 IV 命令行处理不依赖这些界面/聚类组件。
- 新增独立 `iv_batch.py`，输出 PNG、普通数值 NPZ、兼容 GUI 字段的 NPZ 和逐文件 `report.json`，禁止覆盖已有输出目录。

## 其他 review 发现与优化顺序

1. **P1：仓库无法直接完整重建 GUI。** `main.py:2` 导入 `widgets`，`modules/ui_functions.py` 使用 `CustomGrip`，但 Git 仓库缺少整个 `widgets` 目录；`setup.py:5` 还要求缺失的 `themes/`。需要从原完整工程恢复并纳入版本控制，之后才能交付可靠的 Windows EXE。本次没有凭空重写 UI 组件。
2. **P2：主界面仍会在处理期间阻塞。** `run_file_button_iv` 在 GUI 线程调用 `result.get()`；虽有多进程，界面线程仍等待。建议后续用 Qt worker + signals 更新进度并支持取消；本次先修复崩溃和进程清理。
3. **P2：小样本降维缺少参数约束。** `object_data_dimension_reduction` 固定 t-SNE `perplexity=60`、PCA `n_components=3`；筛选后样本不多于 60 或维数不足时会失败。应在调用前检查样本/特征数，并给出可操作提示。
4. **P2：分组分析静默丢弃尾部数据。** `new_function.divide` 使用 `len(conductance)//cacu_num`，最后不足一组的曲线不参与统计；源码注释显示这是原设计。应在 UI 明确显示丢弃数量，或增加是否保留最后一组的选项，以免用户误以为使用了全部曲线。
5. **P2：PSD 参数扫描重复计算。** `new_function.getminN` 连续调用两次 `getMinNInterval`，同一组指数搜索被执行两遍。建议保存第一次结果，并明确处理样本数不足/常量相关系数为 NaN 的情况。
6. **发布可追溯性不足。** 建议在标题栏、日志及导出报告中写入版本/commit，并在发布前用新旧 TDMS 固定样本跑 CI。此次现象表明“GitHub 最新代码”和“组员正在运行的 EXE”可能不同。

## 使用修复版（命令行）

在本项目目录执行，推荐独立虚拟环境：

```sh
python -m pip install -r requirements-iv.txt
python iv_batch.py "C:/Users/Lifa Ni/Desktop/IV-0.001" --output "C:/Users/Lifa Ni/Desktop/IV-result" --bias-base 0.1 --peak-start -2.5 --peak-end -5
```

`--output` 必须是尚不存在的目录。返回码：0 全部完成，1 未完成，2 部分文件被跳过；具体原因见 `report.json`。

沿用旧 GUI 默认图像范围时，微小电流及导数可能落在显示范围之外，**这和解析为空不同**。提供样本的演示图采用下列显式显示范围（仅改变显示，不改变扫描筛选或导出数值）：

```sh
python iv_batch.py "IV-0.001" --output "IV-result-readable" --log-di-range -9 -3 --current-range -0.00001 0.00001
```

`forward.npz` / `reverse.npz` 包含全部重采样结果；`forward_logI.npz` 等 8 个文件使用现有 GUI 的 `distance_array`、`conductance_array`、`length_array`、`additional_length` 字段。电压单位 V，原始电流单位 mA，logI 为 log10(|I/nA|)，logG 为 log10(G/G0)。`length_array` 沿用现有 IV 导出的电导辅助字段含义，不是机械位移长度。

运行回归：

```sh
python -m pip install pytest
python -m pytest -q tests -W error::RuntimeWarning
```

设置环境变量 `IV_SAMPLE_DIR` 为新样本解压目录后，执行 3 个真实新样本的 99/88/80 条扫描回归；设置 `IV_OLD_SAMPLE` 为提供的旧 TDMS 文件路径后，执行旧样本 auto 模式 32 条和 current 模式 27 条回归。未设置时各自对应的私有样本测试跳过。原始实验数据没有加入代码仓库。
